# Plan: speed up navigation from published HTML to the hub

## Evidence

The [handoff](slow-html-navigation.md) records a 14.9 ms navigation action followed by an 18.86 MB uncompressed, `no-store` HTML response. The browser spent about 2.03 seconds waiting and 1.27 seconds receiving it. This was one capture on revision `70bed85b`; its waiting time does not identify a server, tunnel, or network cause. The captured handler was not independently confirmed.

`src/hub-runtime.mjs:204-212` embeds both browser bundles in every generated hub page. Existing local `dist/diff-app.js` and `dist/hub-markdown.js` measure 8,368,945 and 10,452,292 bytes. `build.mjs` bundles a worker into the diff script and builds both bundles without minification. The vendored Lavish HTML handlers read the page, inject the SDK and send it uncompressed with `no-store` (`vendor/lavish/src/server.js:2302-2350, 2353-2438`). The source therefore identifies a large avoidable payload, even though it does not prove what caused the captured response wait.

## Implementation

1. Enable esbuild minification for the worker, diff and Markdown browser bundles in `build.mjs`. Build the app and compare generated bundle sizes to the existing sizes above. Keep the current single-file hub generation and inline configuration, scripts and styles. This avoids changing asset URLs, cache authorization, worker delivery or portable export. If minification breaks the embedded worker or rendering, fix that before proceeding.
2. Assess the compression side channel before enabling gzip on private HTML: the page includes capability-bearing configuration and injected authentication material alongside potentially attacker-influenced content. `no-store` prevents caching, not response-length leakage. Identify whether an attacker can cause repeated chosen content to share a compressed response with a stable secret and observe its length. If that risk cannot be ruled out or mitigated, do not compress that response; retain minification and report the constraint rather than assume compression is safe. Avoid logging secrets during this assessment.
3. If safe, add negotiated gzip to both vendored artifact HTML handlers after SDK injection, retaining `Cache-Control: no-store`. Honor explicit coding quality values and wildcard precedence, including `gzip;q=0`, `*;q=0`, identity's default acceptability and `identity;q=0`; select only an acceptable representation, return 406 if neither is acceptable, and merge `Vary: Accept-Encoding`. HEAD returns the same selected representation headers as GET without a body. Set the correct representation length. On compression failure, use identity only if acceptable; otherwise fail without sending partial or mislabeled bytes. Preserve authorization, SDK injection, authored asset serving and unrelated responses.
4. Compression is asynchronous: immediately before sending the prepared representation, recheck the active load after the last compression await. Preserve each handler's existing semantics: the legacy handler verifies its requested token and revision; the path handler rejects a change only when there was an active generation before reading, comparing its token and revision, while preserving its no-active-generation behavior. Return the existing expired-load response when required. Do not mark a pinned document read until the successful response is ready. Compression may reduce transfer but is not assumed to fix response-start latency.
5. Keep the embedded-worker fallback, authored resources, annotation SDK, navigation confirmations and save-target guards intact. The generated HTML still contains its scripts; verify export works rather than assuming it. Do not add a separate benchmark framework, immutable asset service or lazy-loading system.

## Focused verification

- Build using the repository's documented build command. Record resulting diff and Markdown bundle sizes and confirm generated hub HTML still includes its scripts and fresh runtime configuration.
- If gzip is enabled, extend `vendor/lavish/test/server.test.js` to cover both handlers, negotiation (wildcards, quality values, identity, 406 and HEAD), `Vary`, `no-store`, decoded equality, SDK injection and compression failure. Add a deterministic regression that pauses compression, changes the active load, then releases it and asserts the old response expires; cover both handlers and the path handler's no-active-load semantics. Run `node --test vendor/lavish/test/server.test.js`.
- Mandatory browser regression: extend the existing Playwright/real-owner harness in `test/hub-e2e.mjs` or an equivalent isolated harness to build and execute the production minified diff and Markdown views and actual worker, and navigate from published HTML back to the hub. Check worker rendering rather than merely worker creation, and exercise fallback where practical. Run `node test/hub-e2e.mjs` with its documented `hc` prerequisites. The lightweight `test/hub-browser.test.mjs` substitutes the app script and alone is not sufficient.
- Run `node --test vendor/lavish/test/export-bundle.test.js` and add a focused exported-hub browser check using the built scripts, offline and without a server, where the existing harness permits. Check self-contained rendering and report owner-dependent actions or a concrete harness blocker; also preserve authored resources, annotation controls and save targets. Run tests sequentially with isolated temporary state.
- Have the operator run the demo with browser performance monitoring enabled and compare the same published-HTML-to-hub navigation with the prior experience. Record response size and observed timing without recording capability URLs, request bodies, headers, private paths or tokens. No arbitrary numerical target is required. If response start remains slow, report it separately and investigate based on the new trace.

No live restart or reload is authorized by this plan. The operator must explicitly say “restart now” before either action. Do not use `just demo` to restart or reset the existing fixtures and registrations.
