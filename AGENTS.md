# Working on lavish-hub

Last verified: 2026-11-14

Testing and test-retention guidance are in [TESTING.md](TESTING.md). User and
agent docs are in [docs/](docs/README.md). Update them when behavior changes.

Code comments explain why, not what, except for succinct type and function
doc comments. Do not run a deslop pass on code comments. Run a deslop pass
on changed documentation once at the end of a task, not incrementally.

Use jj. Start with an empty change, review `jj diff --git`, and commit only
files you changed. Use imperative commit messages of at most 72 characters,
without a trailing period. Leave the working-copy change empty after
committing. Advancing and pushing `main` is authorized through the development
process below; other bookmark moves require the operator's approval.

This is a personal interactive tool. Prefer pragmatic changes and short cycle times;
general-user compatibility and checkout-runtime installation are not required.

This is a public repo. Keep private names, work details, credentials, hostnames,
and absolute home paths out of code, tests, and docs. Use `$HOME`/XDG paths in
examples. Never read or print secrets to inspect an environment or config.
Keep macOS and Linux working. Lockfiles are generated by npm, not hand-edited.

For UI work, read [docs/ui-conventions.md](docs/ui-conventions.md).

When changing delivery, keep the guarantees in
[docs/feedback-routing.md](docs/feedback-routing.md#delivery-guarantees): each
save or action keeps the target it arrived with, and Create PR records its
launch attempt before calling herdr. Generated pages and worker files stay
local and outside the reviewed repository.

## Development process

- Make every file edit in your own jj workspace under `.workspaces/<name>`
  (see the `jj-workspaces` skill), based on the revision the operator named
  (default: `main`). Commit only your task as new leaf commits.
- Finish every task by integrating it into `main`. Orchestrators must personally
  run integration, not delegate it. Serialize integration with the shared lock
  file `<primary-checkout>/.workspaces/integration-mutex`, never a workspace-local
  copy. Acquire it atomically with exclusive creation, record your agent session
  ID and workspace as owner, and wait if held. Never bypass an existing owner.
  If policy prevents acquiring the lock or recording its owner, stop and ask the
  operator; do not integrate. Clear a stale lock only after operator confirmation
  that its owner is no longer integrating. Release only a lock you own.
- While holding the lock, fetch `origin` and default to rebasing all local
  changes onto `main@origin` for linear history, including unpublished ancestor
  commits and local `main` commits, not just the current task's commits. Their
  presence alone is not a reason to stop. Preserve unrelated work; coordinate
  before rewriting another session's active commits, and stop if preservation
  is uncertain. This rebase default does not authorize publishing unrelated
  work that is not approved for publication. Resolve conflicts before QA;
  the lock, full QA, and no-force-push requirements still apply.
- Run `just check` in that workspace. It installs dependencies exclusively,
  generates and audits the full screenshot matrix first, then runs the full test
  and real-`hc` e2e suites with separate temporary state and ports. Once it prints
  `Screenshots ready`, visually inspect the PNGs in the announced artifact
  directory at original size while the remaining checks run. Eight primary
  wide/dark images represent the larger static and real-Lavish diagnostic
  matrices; selected pages can have additional scroll captures. Wait for exit zero
  and inspect `status.json`; screenshot readiness alone is not a pass. Record
  visual inspection separately: automated checks cannot sign it off.
  The runner's bounded concurrency is allowed; do not overlap independent test
  commands or `npm ci` in one checkout. The public commands enforce a shared
  `.checks/lock` because dependency installation and standalone `shots/` output
  are mutable. Direct test invocations bypass that lock and must not overlap.
  All checks remain mandatory, including for documentation changes; missing
  prerequisites (including a working `hc` service) block integration. Automated
  tests mock `herdr-app` and do not require its desktop application. Any fixes
  require fresh QA on the exact commits to be pushed.
- After QA passes, move local `main` to the tested task tip and push only
  `main` to `origin`, never force-push. If remote `main` advances, fetch,
  rebase onto the new `main@origin`, and repeat all QA before moving local
  `main` to the newly tested tip and retrying. Replacing your previous local
  integration tip is allowed; discarding unrelated work is not.
- Hold the lock through confirmed push success, then release it and remove
  the task workspace using the `jj-workspaces` skill. On failure or
  cancellation, release your lock and report the unmerged task and any local
  bookmark movement; reacquire the lock and restart from fetch before retrying.
